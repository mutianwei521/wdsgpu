# Synthetic benchmark networks

Twenty-three randomly generated, hydraulically plausible distribution networks
ship with this repository. They are the "Synthetic-M0..M19" and "Synthetic-S0..S2"
rows of the 52-network verification suite (`data/benchmark_report.txt`,
`data/tables/tab_full_benchmark.csv`) and the `rand_main_*` / `rand_small_*`
stems of the regression suite (`data/regression_report.txt`, item 1: 23 of the 25
steady-state alignments).

| family | files | stems used by the scripts | generator seed |
|--|--|--|--|
| main | `networks/random_main/rand_0000.inp` .. `rand_0019.inp` (20) | `rand_main_0000` .. `rand_main_0019` | 20260803 |
| small | `networks/random_small/rand_0000.inp` .. `rand_0002.inp` (3) | `rand_small_0000` .. `rand_small_0002` | 11 |

The files stay in `networks/random_main/` and `networks/random_small/` because
that is where `scripts/align.py` (`resolve_inp`), the regression driver, the
gradient checks and the `__main__` smoke tests of `dgga/autodiff.py` look for
them; the directory names are part of the recorded stems.

## Provenance

Every file was written by `generate_random_networks.py` in this directory
through the EPANET 2.2 toolkit (`EN_*` project API, saved with
`EN_saveinpfile`). The generator lays networks out the way real ones are laid
out: Poisson-disk sampled junctions reduced to a planar Gabriel graph and
thinned towards a spanning tree by a random loop ratio; a smooth random
terrain; reservoirs on high ground with heads chosen for a target service
pressure; log-normal demands; pipe diameters sized from accumulated demand on a
shortest-path tree at a target velocity and snapped to a commercial catalogue;
and an acceptance gate on service pressure (15 to 120 m) and velocity (up to
4 m/s). Node ids are `J1..Jn`, `R1..R2`; there is no utility data and no
third-party provenance in any of them. LPS units, Hazen-Williams, 30 to 120
junctions, pipes only.

## Regenerating them

```bash
python networks/synthetic/generate_random_networks.py --verify
```

regenerates both families into a temporary directory and compares SHA-256
with `SHA256SUMS.txt`. Measured on the authors' workstation (Windows 11 x64,
`epanet22.dll` from WNTR 1.5.0, numpy 2.5.1, scipy 1.18.0): all 23 files
regenerate byte for byte. Whether that holds on another platform depends on
the C runtime's `printf` inside `EN_saveinpfile`; the shipped files are the
canonical artefacts either way, and `--verify` reports per file.

The script needs numpy, scipy and an EPANET 2.2 shared library. It looks for
the library inside the installed `wntr` package (the same library the rest of
this repository uses as its reference engine); pass `--dll` to use another
build.
