## 3. Darcy-Weisbach
阻力常数（不含 f，解析一次算好）：hydcoeffs.c:97-99
    case DW: link->R = L / 2.0 / 32.2 / d / SQR(PI*SQR(d)/4.0);
DWpipecoeff hydcoeffs.c:578-620：
    591-595 q=|Q|; r=R; ml=Km; e = Kc/Diam(相对粗糙度); s = Viscos*Diam
    600-605 层流 (q <= A2*s, A2=500π 即 Re<=2000)：Hagen-Poiseuille
            r = 16πs·R;  hloss = Q*(r + ml*q);  hgrad = r + 2*ml*q     <-- 无 f
    609-615 紊流：f = frictionFactor(q,e,s,&dfdq)
            r1 = f*r + ml;  hloss = r1*q*Q;  hgrad = 2*r1*q + dfdq*r*q*q
    618-619 P=1/hgrad; Y=hloss/hgrad
frictionFactor hydcoeffs.c:623-670，w = q/s = Re·π/4：
  Re>=4000 (w>=A1=1000π) - Swamee-Jain **显式**逼近 Colebrook-White，644-651：
      y1 = A8/pow(w,0.9);   A8 = 5.74*(π/4)^0.9
      y2 = e/3.7 + y1;
      y3 = A9*log(y2);      A9 = -2/ln(10)
      f  = 1.0/(y3*y3);
      *dfdq = 1.8*f*y1*A9/y2/y3/q;        <-- **解析导数，源码直接给出**
  2000<Re<4000 - Dunlop 三次插值多项式，656-668：
      y2 = e/3.7 + AB;  y3 = A9*log(y2);  fa = 1/(y3*y3);
      fb = (2.0 + AC/(y2*y3))*fa;         r = w/A2;
      x1 = 7fa - fb;  x2 = 0.128 - 17fa + 2.5fb;
      x3 = -0.128 + 13fa - 2fb;  x4 = 0.032 - 3fa + 0.5fb;
      f = x1 + r*(x2 + r*(x3 + r*x4));
      *dfdq = (x2 + r*(2*x3 + r*3*x4))/s/A2;
  常数 hydcoeffs.c:23-31。
=> **全程无内迭代**：没有 Colebrook 的隐式不动点循环，两支都是闭式；
   且 EPANET 自己就用解析 df/dq 组装 hgrad，说明 f 对 q 处处可解析求导。
   可微性隐患只有 Re=2000 与 Re=4000 两个分段接点（值连续、导数近似连续，非严格 C1）。

## 4. 批量+可微友好度排序（好 -> 差）
 (1) 水池：最友好。只是把节点加进 fixed_head 向量；进 F 的路径 linkcoeffs.c:240/251
     dense 路径已经有（solver.py:1558-1561 g1_row/g2_row）。零新分支。
     代价：只有边界满/空池的 TEMPCLOSED 要么忽略（并在文档里声明），要么按下面 (3) 处理。
 (2) D-W：次友好。纯逐元素系数运算，两个 torch.where 阈值（Re 2000/4000），
     解析导数已在源码里，形状与 H-W 完全一致，不碰装配结构。批内不同场景阈值不同，
     用 where 即可，无结构差异。
 (3) 泵：最麻烦但仍**不改结构**。三处离散门：
       (i)  XHEAD/CLOSED/setting==0  -> P=1/CBIG（值切换，可用 mask 融合）
       (ii) CUSTOM 曲线分段查找 curvecoeff:818-822（批内每个场景落在不同段
            -> 需要 searchsorted + gather，可向量化）
       (iii) hgrad 的 RQtol/CBIG 夹取（clamp，逐元素）
     真正的难点在状态不动点循环 hydsolve:165-179：批内场景收敛步数和状态轨迹不同，
     需要 per-scenario 的 frozen mask。但泵的状态只影响 P/Y 的取值，
     不像 PRV/PSV(ACTIVE, hydcoeffs.c:972-975/1024-1027) 那样把行改成 Dirichlet 约束，
     也不像 FCV(ACTIVE, 1075-1083) 那样注入 ±q，所以批量可以纯靠 mask 完成。
 附注：PRV ACTIVE 还读 Xflow[n2]（hydcoeffs.c:973），依赖 matrixcoeffs.c:185-194 的
     装配顺序（valvecoeffs 必须在 nodecoeffs 之后），这是阀门族比泵难的另一个原因。
