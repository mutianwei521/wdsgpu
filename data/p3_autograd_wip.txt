§0 接口（缺省一律不变；铁律三）
  solve(..., assemble="csr", linear_solver="cudss") 与
  autodiff.solve_unrolled(..., assemble="csr", linear_solver="cudss")
  在 **requires_grad 下不再 raise**，线性解那一段走 _CudssSolveFn。
  缺省仍是 assemble="dense" + linear_solver="dense"，数值与梯度逐位不变。

  新增可调项（都不改缺省行为）：
    solver.cudss_grad_refine = 2   反向解 λ 的迭代精化步数（与前向同为 2）
    solver.cudss_grad_slots  = 1   反向复用前向数值分解的并发槽数（见 §2）
    solver.cudss_counters(reset=False)
        → dict(factorize, solve, bwd_solve, bwd_reuse, bwd_refactorize)
    cudss_cache_info() 末位新增 slot（纯前向恒为 0）

  数学（§1c 原文的落地）：把整段当**精确解算子** x = A^{-1}b 微分，
    ∂L/∂b = A^{-T}·∂L/∂x = A^{-1}·∂L/∂x    （A 对称，A^T = A）
    ∂L/∂A|_{ij} = −λ_i·x_j  ⇒  grad_data[k] = −λ[row[k]]·x[col[k]]
  A 的对称性不是假设：装配里非对角两处 (n1,n2)/(n2,n1) 取自同一段
  `-Pm[:, lk_both]`、同序散射（solver.solve 的 `vals = cat[...]` 前两段），
  对角是 +P 之和、emitter 只加对角 ⇒ **位型与数值都逐位对称**。
  grad_data **不做对称化**：CSR 的 (i,j)/(j,i) 是两个独立槽，各自的
  −λ_i x_j / −λ_j x_i 会在上游 scatter_add 的反向里对同一条链路的 P 求和，
  正好等于 λ_i x_j + λ_j x_i（手算与 §1 的 FD 都对上）。

  **哪些参数支持**：全部。梯度只从 (csr_data, F) 这两个口子回流，而
  d / rh / r_hw / ke / emitter / 泵 θ 都是通过普通 torch 算子进 csr_data 与 F 的，
  所以没有"某类参数做不到"的分支。**唯一做不到的是二阶导**（见 §5）。

§2 "反向复用前向那一次数值分解" - 做到了，但它只值不到 1%（本轮最重要的订正）

 2.1 一份 cuDSS state 同一时刻只持有**一个**数值分解
  展开 K 步的图：前向按 1..K 依次 factorize，反向按 K..1 依次要用。
  单份 state 下只有最后一步的分解天然还在，前面 K−1 步的都已被顶掉。
  实现给出两条路，都不静默：
   · `cudss_grad_slots = n`：前向轮转取槽 slot = i mod n，n ≥ K 时每一步各占
     一份 state ⇒ **反向零重分解**；
   · slots < K 时越界的那些步在反向里按保存的 csr_data 重做一次数值分解，
     计入 `cudss_counters()["bwd_refactorize"]`。
  另有 gen 计数器：state 每 factorize 一次 +1，反向比对 gen 才决定复不复用，
  被 LRU 逐出（solver 已 free）也判定为不可复用。**"复用"从不靠假设，靠核对。**

  4×3.7775 = 15.11 ms（§3.2）。省掉 7 次 factorize = 7.1 ms，占整个 8 轮
  fwd+bwd 的 224.7 ms 的 3.2%，而实测被节点噪声吃掉，量不出来。
  代价那边：slots 1→8 常驻从 2266.2 涨到 2678.2 MiB（+412 MiB，边际 ~59 MiB/槽）。
  ⇒ **缺省 cudss_grad_slots = 1**：省 412 MiB，多付 <1% 的时间，
    counters 里如实记 bwd_refactorize。要"零重分解"的场合（比如做本表这种
    审计、或 factorize 相对昂贵的网）把它调到 ≥K，并同步把 cudss_cache_max
    调到 ≥slots（不调直接 raise，不让人白花显存）。

 2.4 **对方案 §1c 那句"这是稀疏路线的结构性优势"的订正**
  §1c 写"grad_b = A^-1 grad_x - **复用同一个分解**，多一次 solve"。
  前半句在**单次线性解**上完全成立（隐式伴随、或展开图的最后一步）；
  但在展开 K 步的图上，"复用"要么多占 K 份 state，要么就是 2K−1 次 factorize。
  更要紧的是：**即使做到了零重分解，收益也只有 <1%**（§2.3） -
  因为 nvmath 1.0.0 的显式批量让 solve 成了一条与 Nj 无关的地板
  （3.78 ms/次 @ky4 B=256），factorize 反而是小头。
  ⇒ 真正的结构性优势不在"省一次 factorize"，在 §3/§4：
    稠密反向的 **O(B·Nj³) Cholesky VJP** 与 **每轮两份 [B,Nj,Nj] 的激活**。

 3.3 **审计估的"9.4x 降到 7.7x"方向就错了 - 实测是升，不是降。查清了原因**
  审计（p2_adversarial_wip §10 前置三）的算法是：
    cudss 每轮 fact+3solve → fact+4solve（8.69 → 11.27 ms）✓ 方向与量级都对；
    dense 每轮 81.1 → **86.3** ms - 理由是"cholesky_solve 只占 5.5/77"，
    即**把稠密反向定价成"再来一次 cholesky_solve"**。
  实测 dense 每轮 79.14 → **1538.3** ms，即反向 1459 ms = 正向的 **18.4 倍**，
  比审计的定价高 **270 倍**。原因是 torch 通用 autograd 穿 `linalg.cholesky` 的
  VJP 不是"再解一次"：Cholesky 的反向要在 [B,Nj,Nj] 上做三角解 + matmul
  （O(B·Nj³)），3 次 cholesky_solve 各自还要向因子 L 回传一个 [B,Nj,Nj] 的外积，
  2 步精化里的 `(A*Hj^T).sum(-1)` 也各留一份 [B,Nj,Nj] 的激活。
  ⇒ 一句话：**审计把"稠密反向"当成了 O(B·Nj²)，实际是 O(B·Nj³) 且常数很大。**
    cudss 那一侧审计估得很准，错的全在稠密那一侧。
  （这笔账还没完 - 见 §6 的公平性自查：如果给稠密也手写一份伴随，倍数会掉回
    什么水平，必须一起报，否则就是 F5 那种"基线自缚"。）

§6 公平性自查：那 29~39x 里有多少是"稀疏拿了自定义反向、稠密没拿"
  这是 F5 那类问题（基线自缚）的正面回答，**我自己先查，不等审计来问**。
  §3 的稠密侧是**仓库现状**：torch 通用 autograd 穿 `linalg.cholesky`。
  而稀疏这边是我们本轮手写的伴随。把同样的手写伴随也给稠密一份
  （DenseAdjoint：前向 chol + 1+2 次回代，反向 `cholesky_solve` 复用同一个因子、

§8 遗留 / 没做的（写清楚，别让人以为做了）
  E1 二阶导做不到（§5），需要时用 dense。
  E2 float32 仍只在 dense 通路上有；cudss 通路一律 f64。
  E3 `cudss_grad_slots` 的缺省是 1 - 也就是**缺省不是"零重分解"**。
     要那个性质请显式调大（并同步调大 cudss_cache_max）。理由见 §2.3：
     零重分解值 <1%，不值得让缺省多吃 412 MiB。
  E4 没有做"GPU 上的隐式伴随"（对收敛解直接解一次 A^Tλ=g）。本轮做的是
     §1c 字面要求的**逐次线性解**的 Function，它服务的是 solve_unrolled /
     solve 这两条展开路线。GPU 隐式伴随需要整装 Jacobian J（含链路/emitter
     两块），不是本轮的 A - 属于后续。
  E5 §1.2 里 City_D / ky4 的 grad d 偏差（6e-4 / 3e-5）**没有被解决**，
     只是被归因（展开路线在 κ≥7e8 的网上的固有差，dense 同样有）。要在这类网上
     要准梯度，用 ImplicitGGASolve。
  E6 本轮只在 gpu_5090 队列上跑（未用 gpu_4090，更未用 hp_4090）。
  E7 §3.1 的 dense 侧 OOM 边界是在"卡上只跑这一件事"的前提下测的；
     真实训练里还有模型参数与优化器状态，边界只会更靠左。
