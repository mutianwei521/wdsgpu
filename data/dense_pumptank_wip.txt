## 1. 水池：单帧内 ≡ 定水头节点

 依据（已精读，未重复考证）：矩阵只有 Njuncs 阶（hydsolver.c:123）；tank/reservoir
 编号排在 Njuncs 之后（types.h:816-818）；只经 linkcoeffs 的 F += P*NodeHead
 （hydcoeffs.c:240,251）进右端；单帧内 NodeHead[tank]=tank->H0 由 inithyd 设死
 （hydraul.c:110）；tanklevels 只在时段之间跑（hydraul.c:247,655-657）。
 ⇒ dense 直接复用既有的 g1/g2 定水头接地装配（solver.py 装配索引段），零新分支。

## 2. tankstatus 守卫：选了"静态必要条件 + 事后精确判据"双层，不是二选一

 tankstatus（hydstatus.c:401-476）是水池与定水头节点的**唯一**差别：
   满池 H>=Hmax-Htol && !CanOverflow（:444）/ 空池 H<=Hmin+Htol（:461）
   ⇒ 泵按方向（:449/:466）或 cvstatus（:454/:471）把连接管置 TEMPCLOSED。
 · 第一层（构造期，默认开）_check_dense_tank_bounds：按任务书要求，H0 落在
   [Hmin+Htol, Hmax-Htol] 之外直接 raise NotImplementedError。Htol 取项目既有口径
   self.htol（input1.c:27 HTOL=0.0005，INP [OPTIONS] 可覆盖），未自造常量。
 · 第二层（solve 收敛后，恒开）_check_dense_tank_status：用**实际收敛解**逐字复核
   完整判据（含选端逻辑 :423-438 的"n1 是定水头就不回退到 n2"、reservoir 跳过
   :436-438、泵方向、cvstatus 三分支）。dense 的水池水头由调用方经 res_head_ft
   批量给定、可与 INP 的 H0 无关，所以这一层是必须的，不是冗余。
 · 第一层是必要条件、不是充分条件，故给了 dense_tank_bound_check=False 的显式出口；
   关掉它也不会静默算错 - 第二层照样 raise。实测证据见 §4。

## 3. 泵：移植 autodiff.solve_unrolled 的泵支（未重造）

 三条曲线分支 + 钳位齐备，与 _PY_np（epanet 逐位路径）同源：
   幂函数 h0=SQR(w)*H0(:737)、r=R*pow(w,2-N)(:740)、hgrad=n*r*q^(n-1) 带 RQtol 钳位
        (:770-778)、n==1 线性支(:781-785)
   CONST_HP hgrad=-r/q/q 夹在 [RQtol, CBIG](:746-762)
   CUSTOM  curvecoeff 分段线性(:794-831) → hgrad=R*w(:731), hloss=H0*w²+hgrad*Q(:732)
   NOCURVE P=1/CSMALL(:709-714)；CLOSED 或 setting==0 → P=1/CBIG, Y=Q(:696-701)
 **CUSTOM 分段查找已按任务书要求批量化**：autodiff 的 O(K·B·泵) python 双循环
 （autodiff.py:853-866）→ torch.searchsorted(side='left') + gather。
 等价性论证：C 的 `while (k2<npts && x[k2]<q) k2++`（:819）就是"首个 x[k2]>=q 的
 下标"，与 searchsorted(side='left') 语义完全一致；夹取 :820-821 = clamp(idx,1,npts-1)。
 前提是曲线流量严格递增 - 构造期断言，不满足 raise（不静默近似）。
 padding 用 +inf：q 高于末点时 searchsorted 返回 npts，被 clamp 到 npts-1，正好等于
 :821 的末段外推。

 CUSTOM 新旧选段数值差（Anytown_wntr, 3 台 CUSTOM 泵, B=64, q 随机 0.3~3x）
   max|ΔP| = max|ΔY| = 0.000e+00   （逐位一致）
 耗时（Anytown_wntr，20 次平均；"旧"只算选段，"新"是整条泵支）
   B=8    新 0.256 ms | 旧 0.034 ms
   B=64   新 0.307 ms | 旧 0.162 ms
   B=256  新 1.775 ms | 旧 1.179 ms
   B=1024 新 2.218 ms | 旧 4.728 ms   ← 旧法**只做选段**已是新法整支的 2.1 倍
 旧法 O(B·泵) 线性增长、新法近乎常数，批越大差距越大；B 小时 python 循环反而更快
 （张量算子固定开销），但 dense 路径存在的意义就是大 B。

## 4. 泵关停（XHEAD）：选了"会被关停就报错"，不支持传入冻结状态

 理由：solve() 第 1430 行附近明确拒绝 link_status/link_setting/status_machine
 三个入参（"仅 epanet 模式"）。要支持冻结状态，就得同时把 link_setting 打通到
 TCV 的 Km 重算（hydcoeffs.c:929-932）与阀的 MISSING 语义，属于另一件事；
 半支持会造出一条"只对泵生效、对阀静默忽略"的入参，比不支持更危险。
 所以选：_check_dense_pump_shutoff 在收敛后逐字复核 pumpstatus
   linkstatus(:147-151) 对 status>=OPEN 且 LinkSetting>0 的泵调 pumpstatus(k,-dh)，
   dh=H[n1]-H[n2] ⇒ 扬程增益 = H[n2]-H[n1]；
   hmax = CONST_HP ? BIG(:223-227) : SQR(setting)*Pump.Hmax(:231)；
   增益 > hmax+Htol ⇒ XHEAD(:235)。2.2 不查最大流量(:237 注释)。
 命中即 raise，**不默认泵永远开着**。21 网实测：无一命中（见 §5）。

    ⇒ 这是"展开路径含泵时在泵节点上的既有偏差"，autodiff.solve_unrolled 早就有，

  · 附带发现：Net3 与 ky4 的 GGA 迭代在 relerr≈1e-9 处进入舍入极限环，**epanet
    路径同样如此**（K=100 时 dense relerr=7.0e-9 / epanet 6.6e-9），所以拿
    accuracy=1e-12 去要求收敛是做不到的；对这两个网做梯度时应走 B（隐式）。
  · 另一处易踩的坑（记下来免得下次重查）：Net3 的定水头节点 93 "Lake" 只经一条

    量级），而 h=1e-4 的中央差分噪声是 ±5e-3 - 该坐标 FD 无效，别当成梯度错。
