[2] PRV 状态机 (hydstatus.c prvstatus:242-299), hset = Node[n2].El + Setting
    hml = Km*Q^2 (:267)
    from ACTIVE(:273): Q < -Qtol -> CLOSED ; h1-hml < hset-htol -> OPEN ; 否则 ACTIVE

    prvcoeff (:942-992):

[7] 稀疏位型是否随场景变化? - 不变。这是本轮最重要的结论。
    smatrix.c createsparse(:77-127) 在 openhyd() 阶段调用一次, 输入只有
    Adjlist(拓扑) 与 MMD 重排; Ndx[k] 在 paralink(:271-297) 里按并联关系
    定死; 之后 factorize/storesparse/sortsparse 全部只依赖拓扑。
    整个 hydsolve 循环里没有任何一处重建 Ndx/NZSUB/Row。
    每轮 matrixcoeffs:179-182 只是 memset 清零, 再往同一批槽位累加。
    => 状态切换 (OPEN/CLOSED/ACTIVE) 只改 Aii/Aij/F 的**数值**:
       CLOSED: P=1/CBIG=1e-8 (非对角 ~0, 但槽位还在)
       ACTIVE PRV/PSV: 非对角写 0 (prvcoeff 提前 return 不写 Aij), 对角 +1e8
    => B 个场景可以共用同一个 [B, Nj, Nj] 稠密 A, 一次批量 Cholesky 解决。
       无需按状态分组 (bucketing), 无需可变稀疏结构。

[8] 批量移植的真实代价清单
  (a) 可 torch.where 纯向量化, 便宜:
      - CVPIPE 状态判定 (cvstatus 三分支, 全是逐链路比较)
      - valvecoeff/tcvcoeff/pipecoeff 的 closed 分支 (dense 路已有, solver.py:1536)
      - PRV/PSV/FCV 各自 4 个 case 的转移: 用 one-hot(旧状态) 加权四个候选,
        即 S_new = Σ_c 1[S_old==c] * f_c(h1,h2,Q)。每个 f_c 都是纯比较, 可批。
  (b) 需要按 batch 维散射的 big-M 注入, 中等:
      - ACTIVE PRV: A[b, j, j] += CBIG * m[b,k];  F[b, j] += hset*CBIG*m[b,k]
        其中 m[b,k] = 1[S[b,k]==ACTIVE]。非对角要写成 (1-m) 乘因子而非 +=,
        因为 prvcoeff ACTIVE 分支是「跳过写入」不是「减去」。
      - Xflow[n2] 的条件项 (:976) 是 max(Xflow,0) 形式, 可用 clamp 批量化。
  (c) 真正的串行残留, 但代价小:
      - valvecoeffs(:301-329) 对 Nvalves 的循环有跨阀依赖: fcvcoeff:1075-1076
        修改 Xflow, 而后续 prvcoeff:973/psvcoeff:1025 会读 Xflow。
        => 必须保留 Python 层对 Nvalves 的顺序循环 (Nvalves 通常 <50),
           但循环体内对 B 维完全向量化。这是 O(Nvalves) 次 kernel launch,
           不是 O(B) 次。可接受。
  (d) 不可微点 (梯度侧的真问题):
      - 状态是 argmax/阶跃, 处处梯度为 0 或不存在。B 个场景状态不同时,
        每个场景各自落在不同的分片光滑区。
      - 但: 只要在**收敛点**状态已冻结, 对固定状态的隐函数定理仍成立,
        d(H,Q)/d(theta) 可由最后一次线性系统反解得到 (与现有 dense 路一致)。
        状态本身贡献零测度集上的不连续 - 与 EPANET 语义一致, 不是缺陷。
      - big-M=1e8 会把 A 的条件数从现有 κ~1e9 再推高。solver.py:1580-1600
        已记录 f32 下 κ≈1e9 就已经 Cholesky 失败, 必须走均衡+部分主元。
        加 PRV ACTIVE 后 f32 路基本不可用, f64 + 迭代精化仍可。
  (e) 顺带必需但与阀无关:
      - 水池: linkcoeffs:240,251 的 F += P*Head 已存在, 只需把水池头当作
        每轮更新的边界; tankstatus(:401-476) 需要 Hmax/Hmin/CanOverflow。
      - D-W: DWpipecoeff(:578-621) + frictionFactor(:623-671), 纯逐元素, 可批。
      - PUMP: pumpcoeff(:673-792) 有 CUSTOM 曲线分段 (curvecoeff:794-832),
        分段查表在批量下要用 searchsorted + gather。CONST_HP 分支在
        newlinkflows:437-443 还有个 dq 截断, 是逐场景条件。

[9] 一句话答复问题 4
    稀疏位型不随场景变化 (createsparse 只依赖拓扑, hydsolve 全程不重建),
    状态切换只改数值 - 因此一次 [B,Nj,Nj] 批量稠密分解就够, 这条路走得通。
