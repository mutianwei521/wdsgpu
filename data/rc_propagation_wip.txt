2. 两种形状，以及每个脚本选哪种、为什么
--------------------------------------------------------------------------------
【single（28 个）】只有一个 python 步骤。fail-fast 与 accumulate 在这里没有
区别，一律：

    python3 -X utf8 xxx.py
    rc=$?
    echo "XXX JOB DONE rc=$rc"
    exit $rc

  其中 3 个（p2_cudss/p2.sh、p2b.sh、p2c.sh）原本以裸 python 结尾，
  退出码**碰巧**是对的 - 谁在后面补一行 echo 就无声破掉，故一并写显式。
  p4_remeasure/p4r7.sh 带 `P4R_R7_STEPS=4 python3 ...` 前缀，$? 仍是 python 的。

【accumulate（5 个）】多个 python 步骤：
    deploy/paracloud/run_bench.sh          2 处
    scripts/aud_p4/audtbl.sh               2 处（主表 + 12 次显存抽查）
    scripts/audit_p2_adversarial/adv.sh    3 处（主测 + 16 + 6 次显存）
    scripts/audit_p2_adversarial/adv2.sh   2 处
    scripts/p2_f4/f4b.sh                   1 处（run() helper，被调 14 次）

    rc=0
    python3 -X utf8 a.py || rc=$?
    ...
    python3 -X utf8 b.py || rc=$?
    echo "... JOB DONE rc=$rc"
    exit $rc

  **为什么是 accumulate 而不是 fail-fast**：这些都是测量作业，格与格之间互相
  独立。第一格失败就退出会白占一次 GPU 分配，并且丢掉本来能测出来的其余格；
  而这些作业的产物就是那张表，缺格比晚一轮更贵。所以跑完全部、但退出码仍非零。
  f4b.sh 的 `rc=$?` 写在 run() 函数体内 - bash 函数不声明 local 即写全局，
  故 14 次调用共享同一个 rc。

  代价（明说）：只留最后一个非零码，中间失败的具体码会被后面的覆盖。
  作业状态与日志足以定位，没有再引入 rc 数组的必要。

3. 两个故意不修的
--------------------------------------------------------------------------------
  scripts/xfinal/rc/xf_rc_old.sh - P4 终审用来证明 bug 存在的**负对照**
    （作业 1459917 COMPLETED 0:0，对照 1459916 FAILED 3:0）。改了就是销毁证据。

    已经是对的。

  另新增 scripts/rc_probe/rc_old.sh，同样是刻意保留的坏形式（集群对照用）。

4. 证据
--------------------------------------------------------------------------------
【本机 16/16】scripts/rc_probe/check_rc_local.sh
  用桩 python3/nvidia-smi 跑真脚本，比对退出码。覆盖 single 的三种写法、
  accumulate 的"首步失败/末步失败/循环中一格失败/全成功"，以及两个负对照。
  关键一条：accumulate 首步失败（后续成功）必须仍非零 - 这正是旧的
  "末条命令说了算"抓不到的情形。

【集群 4/4】gpu_5090，桩脚本 scripts/rc_probe/（输出存 data/gpu/rc*_14600*.out）
  1460086 rcok   python 退 0            -> COMPLETED  0:0
  1460087 rcnew  python 退 3            -> FAILED     3:0
  1460088 rcacc  首步退 5、次步退 0     -> FAILED     5:0
  1460089 rcold  python 退 3（旧形式）  -> COMPLETED  0:0   <- bug 仍可复现

  注意 rcold_1460089.out 里日志明明白白写着 rc=3，而作业状态是 COMPLETED -
  信息一直都在日志里，是**作业状态**在说谎，所以靠翻日志并不能替代这个修复。

【范围】没有改动任何 .py；工作区 diff 只有 .sh。
  regression_all 前台 51/51 PASS，报告仅墙钟列与 ⑦ city_d 的 1e-16 量级
  atomicAdd 不定项在动（7.351e-16 -> 4.510e-16），实测值逐行不变。

5. 回归用法
